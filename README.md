# 油站网点补货调度

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则验证：`node_modules/.bin/esbuild scripts/verify-rules.mts --bundle --platform=node --format=esm --outfile=/tmp/verify-rules.mjs && node /tmp/verify-rules.mjs`（16 项核心规则断言）

数据默认保存在浏览器 localStorage（页面右上角可一键重置演示数据）。

## 业务闭环

1. 油站缺油（库存低于安全库存）时，站长在「网点库存」列表点「发起补货」，自动带入缺油站和油品。
2. 在「发起补货」页选择调出站、油品、计划量，系统执行两道闸口判定：
   - **调出站**：库存 − 其他在途调拨占用 ≥ 安全库存 + 本次计划量；
   - **调入站**：库存 + 已有待卸量 + 本次计划量 ≤ 罐容。
   - 任一项不足即整体退回，只留「调度退回」存证，网点列表、库存、单据列表全部不变。
3. 通过后生成「待发车」调度单，发车前不占仓位；车辆发出时服务端二次复校，通过后转「在途」，在途量**同时占用两边仓位**。
4. 卸油签收允许少于计划量：调出站按计划量出库，调入站按实收量入库，差额（损耗）立即释放调入仓位，**损耗必须填写原因留档**。
5. 拒收（仅在途）原车退回、库存不动、两边占用立即释放，需填拒收原因；取消分两种：待发车直接关闭（本未占仓），在途取消按原车退回处理，需填说明。
6. 每一步（退回 / 创建 / 发车 / 签收 / 拒收 / 取消）都向「调度存证」追加不可变审计流水，含判定快照、数量变动与原因。

## 分层结构（库存判定、调度存证、页面拆开）

```
src/
├── domain/                 # 库存判定层：纯 TS、无框架/存储依赖，可单测
│   ├── types.ts            #   网点 / 油罐 / 调拨单模型与状态机
│   └── inventory.ts        #   安全库存、罐容、在途占用、签收合法性规则
├── service/                # 调度服务与存证层
│   ├── transfer.ts         #   编排「判定 → 流转 → 结算 → 存证」
│   ├── audit.ts            #   审计流水类型
│   └── repository.ts       #   localStorage 仓储（可替换为 HTTP 实现）
├── store/dispatch.ts       # Pinia：状态、页面视图模型（占用/余量实时推导）、落盘
├── views/                  # 页面层（只做展示与交互，不直接写台账）
│   ├── StationListView.vue #   网点库存列表 + 缺油预警 + 发起补货入口
│   ├── DispatchView.vue    #   调度申请表单 + 实时规则预览（服务端复核为准）
│   ├── OrdersView.vue      #   调度单跟踪：发车 / 签收(损耗) / 拒收 / 取消
│   └── AuditView.vue       #   调度存证流水（可按动作、关键字筛选）
├── data/seed.ts            # 初始网点油罐台账
└── composables/ui.ts       # 跨页面 Tab 跳转与补货上下文预填
```

### 台账口径

- `tank.stock` 始终是本站实测库存：在途期间两边库存都不变，占用由在途调拨单实时推导（不冗余存储，杜绝占用量与单据不一致）。
- 签收时一次性结算：调出按计划出库、调入按实收入库，损耗差额当场释放。
